Deck and card enforce the approval hashes, the mark-with-a-note rule and the visibility values; deck cards `$ref` the card schema instead of repeating it. Rule files enforce the evidence floor shape (non-format rules cite findings, format rules set `basis: template`). Policies enforce the seven keys and the age-band ladder.
- `plugins/tuckcard/skills/cards-core/scripts/validate.py`: picks a schema from the file name, folder or document shape, accepts `--schema` to override, prints one line per problem as `path: /json/pointer: message`, and exits 1 on any problem or 0 when every file passes. Deck files get five cross-file checks: each basis rule appears in the deck's `rules_snapshot` file when it is reachable (the skip is reported both when the file is missing and when it yields no rule ids), every mark has a note, each mark target occurs at least `occurrence` times in its line, each card's category is declared in the deck's `categories`, and each policy value is allowed by the age band's ladder read from `knowledge/rules/policies.yaml` (an unlisted band allows only `omit` for the sensitive keys).

- `scripts/verify_citations.py` resolves a DOI through Crossref and a PMID through PubMed, compares only the metadata fields the finding stores (title ignoring whitespace and case, first author trimmed and case-folded, year exact), reads retractions and corrections from Crossref's `update-to` and `updated-by` lists, and checks a guidance URL against `knowledge/sources-allowlist.yaml` and, when `source.title` is present, the page title. A failure moves the file to `knowledge/quarantine/` with a `quarantine_reason` naming the check, the expected value and the value found; nothing is deleted. `--responses PATH` replays recorded HTTP responses and makes no network call.
- `scripts/index.py` regenerates `knowledge/findings/index.yaml` with one entry per finding, sorted by ID, and writes only when the bytes change. `scripts/validate_rules.py` checks rule schema, cited-finding status, the evidence floor and override legality (including no override of a safety rule or a higher-precedence scope). `scripts/compile_rules.py` merges shipped and overlay scopes, applies `when` then `overrides`, maps context rules to deck categories and records provenance, with no timestamp so repeated runs are byte-identical. `scripts/promote.py` renumbers `L-` findings and overlay rule IDs, rewrites references in rules and gaps, runs the script check, sends passing findings to the shipped folder and failing ones to quarantine, and regenerates the index. They share `scripts/knowledge_files.py` and the M1 schemas and `validate.py`.

### Fixed

- The `validation` job in `.github/workflows/ci.yml` is pinned to `runs-on: ubuntu-24.04`. The `ubuntu-latest` label moved to Ubuntu 26.04, whose `actions/python-versions` manifest carries no Python 3.9 build, so the 3.9 leg failed at `actions/setup-python@v5` before running a single project step, and the 3.12 leg was cancelled behind it. The `3.9` and `3.12` matrix is unchanged, because D-011 and `requirements.txt` rest on the 3.9 floor and the job exists to exercise that floor rather than retire it. `skeleton` stays on `ubuntu-latest`, since it never calls `setup-python`, and `weekly-recheck` is untouched. Found on this repository's first CI execution, at the push of `e353adf`; the workflow was authored at M0 and had never run on GitHub before.
- The ladder skip note for an unreadable `policies.yaml` is collapsed to one line, matching the missing-file case. The test asserts a two-line run. This folds in the M1 nit that review and QA raised at 189d3a3.
- `validate.py` now reports an unresolvable schema `$ref` as one line naming the reference, exit 1, instead of a traceback. The age-band ladder check prints a one-line skip note and still exits 0 when `knowledge/rules/policies.yaml` is missing or unreadable, the same visibility as the basis skip. Both were raised as non-blocking nits by the M1 review.
- `DECISIONS.md` corrects two wordings on the M1 branch: D-010 now says the `allOf` in `deck.schema.json` rejects a personal detail without `group_level`, not `validate.py`, and D-012 now quotes both D-003 sentences that changed at 0031e73.
- The two deck fixtures were named `deck.yaml`, which the M0 private-output guard correctly flagged on every push. Renamed to `deck.fixture.yaml` so the guard and the SPEC section 9 invariant stay strict; schema detection finds them by shape. QA raised it as a regression against the M1 branch.
- `.github/workflows/ci.yml` now matches `renders/` and `out/` at any depth, not only at the repo root, so a force-committed `local/renders/page1.png` or `local/out/x.pdf` fails. Proved by force-adding both files: the step printed both paths and exited 1; after `git rm --cached` it exited 0.
- `CHANGELOG.md` now says the seed-kit commit adds 66 files, the measured count; the tree holds 67 because `LICENSE` predates that commit. `DECISIONS.md` D-003 now describes the liberation-fonts 2.1.5 release accurately: no Assets entries, with binaries attached as file links in the release notes. The decision, URL and files are unchanged. The M0 review raised both wording nits.
- `promote.py` now allocates each new `F-` number against the ids already used, so a second promoted finding can no longer land on an existing id and overwrite it. It also refuses to write to a destination that already exists. Found by the M2 review, which reproduced a shipped `F-0003` being destroyed by a promotion into a pool with a hole at `F-0002`.
- `verify_citations.py` records `exists: none` when a DOI or URL did not resolve, and `exists: script` when it resolved even if the metadata then mismatched. A passing check now writes the status that check supports: a provisional record that meets the active condition becomes `active`, and one that falls short stays provisional with the missing condition printed. This makes the Path B promotion work end to end.
- `validate_rules.py` rejects an override of a safety rule from any scope, including another safety rule, and reports an override cycle with the rule ids that form it. `compile_rules.py` refuses the deck instead of dropping the rules in the loop. A `do` rule now accepts grade D in any scope, because D is guidance from a public-health or professional body whatever the rule's file.
- `validate_rules.py` accepts a contested finding graded A, B or D for a `must_not` rule and still requires an active one for `must`. `DECISIONS.md` D-021 records the SPEC section 3 and section 4 wording this resolves, and that it goes to the person at the M3 gate.
- `promote.py` refuses an incoming finding whose DOI is already held in `findings/` or `quarantine/`, naming the id that holds it, so a second run over the same overlay can no longer duplicate a record. The overlay copies are still left in place.
